# Lemeri AI — актуальный контекст для Claude

> Читай этот файл перед любой работой с репозиторием. Это источник правды о продукте.
> Если чат-память расходится с этим файлом, верь файлу и обнови его после изменений.

## Концепция
Одна функция → одна проблема → одно решение.

- **Проблема:** бизнес теряет клиентов, потому что посетители сайта не получают своевременную консультацию.
- **Решение:** ИИ-продавец (консультант) в виде карточки чата на сайте. Он круглосуточно консультирует, продаёт, рекомендует товары и собирает заявки.
- Lemeri **не позиционируется** как CRM-платформа, корпоративный инструмент или мультиканальный сервис.
- Не обещаем гарантированного роста продаж или конверсии.
- «ИИ может ошибаться» — пишем на лендинге, в карточке, в кабинете и в документации.

## Разделы кабинета (MVP)
1. **Главная** — диалоги, заявки, ответы ИИ, передачи человеку, состояние подключения, баннер тарифа.
2. **ИИ-сотрудник** (`src/components/sales/employee-studio.tsx`) — профиль продавца и тестовый чат с настоящим ИИ.
3. **База знаний** — `KnowledgeManager` в `platform.tsx`.
4. **Карточка и подключение** (`src/components/sales/widget-studio.tsx`) — дизайн по тарифу, установка с проверкой, ссылка и QR.
5. **Диалоги и заявки** — `InboxView`: диалоги и заявки со статусами Новая / В работе / Успешно / Отказ.
6. **Настройки и подписка** — `SettingsHub`: «Тариф и оплата» (`plan-panel.tsx`) и «Компания и аккаунт».

Всё остальное отложено, см. `docs/FUTURE_FEATURES.md`. Флаги — в `src/lib/features.ts`, env `LEMIRI_FEATURES`.

- **Тестовый период (с 10.10.2026 выключен — тарифы действуют):** `LEMIRI_OPEN_ACCESS=1` в `wrangler.jsonc` → `vars`. Всем пространствам выдаётся полный Custom (`resolveAccess` → `openAccess: true`), оплата отключена (`POST /api/billing` → 409 `OPEN_ACCESS`), в кабинете и на лендинге показана плашка «все тарифы открыты бесплатно». Лимит ответов ИИ (2000/мес) продолжает действовать. **Закрыть:** удалить переменную (или `0`) и задеплоить — данные, подписки и пробные периоды не трогаются, всё возвращается как было.
- **Оплата за год — скидка 20%** (`YEARLY_DISCOUNT` в `plans.ts`): Starter $182.40 ($15.20/мес), Custom $278.40 ($23.20/мес). Цены и тексты считаются из каталога (`planPriceUsd`, `planPriceText` в `offer.ts`). Период подписки отдельно не хранится: `intervalFromPeriod` — период длиннее 45 дней = годовой (`Access.interval`). Лимит ответов ИИ при годовой оплате — месячный, обновляется 1-го числа (`resolveAccess` обрезает окно учёта до конца месяца).
- ИИ в Starter и Custom одинаковый. Custom не получает скрытых функций CRM, каналов и автоматизаций.
- Каталог: `src/lib/billing/plans.ts`. Тексты предложения для лендинга и кабинета: `src/lib/billing/offer.ts`, `COMING_SOON` там же.
- Доступ определяется в одном месте — `resolveAccess()` (`plans.ts`); загрузка из БД — `workspaceAccess()` (`src/lib/billing/access.ts`). Через них работают API, виджет и ИИ.
- **Пробный период:**
  - 14 дней от регистрации владельца — один раз на аккаунт;
  - для аккаунтов, созданных до запуска биллинга, отсчёт идёт от `TRIAL_EPOCH` = 2026-10-10 (env `LEMIRI_TRIAL_EPOCH`).
- **Конец пробного периода или подписки:**
  - ИИ не вызывается — модель не тратит токены;
  - посетитель получает просьбу оставить контакты;
  - форма заявки работает;
  - владелец получает уведомление (не чаще раза в сутки).
- **PAST_DUE:** ИИ работает ещё 7 дней после конца периода, в кабинете предупреждение.
- **Старые планы:** START → STARTER, GROWTH → CUSTOM (`normalizePlan`). Старые price id Stripe распознаются.
- **Даунгрейд:**
  - настройки Custom (`widget.design`, `widget.presets`) остаются в базе;
  - показывается дизайн, доступный тарифу (`resolveLook`);
  - сохранение с меньшего тарифа не удаляет поля старшего (`mergeForTier`);
  - изменить их без Custom нельзя — API отвечает 402 `PLAN_REQUIRED`.
- `LEMIRI_COMP_WORKSPACES` — список id пространств с бесплатным Custom (для своих).

### Биллинг — Paddle (по умолчанию), Stripe как запасной (`BILLING_PROVIDER=stripe`)
- **Env:** `PADDLE_API_KEY`, `PADDLE_CLIENT_TOKEN`, `PADDLE_WEBHOOK_SECRET`, `PADDLE_ENVIRONMENT=sandbox|production`, `PADDLE_STARTER_PRICE_ID`, `PADDLE_CUSTOM_PRICE_ID` (помесячно, обязательны), `PADDLE_STARTER_YEARLY_PRICE_ID`, `PADDLE_CUSTOM_YEARLY_PRICE_ID` (за год, необязательны — без них вариант «За год» показывает «Оплата скоро»; `PADDLE_API_BASE` — только для локальных тестов). Stripe: `STRIPE_*_YEARLY_PRICE_ID`. Модуль `src/lib/billing/paddle.ts`.
- **Период оплаты:** переключатель «Помесячно / За год» над тарифами в кабинете и в форме оплаты; `/app/checkout?plan=…&interval=year`, `POST /api/billing {…, interval: "month"|"year"}`, в `custom_data` транзакции пишется `interval`. Смена месяц ⇄ год у живой подписки — тот же `PATCH` (`prorated_immediately`), при `past_due` — 409 `PAST_DUE`.
- **Оформление:** «Выбрать Starter/Custom» → `/app/checkout?plan=…` (`components/billing/checkout-page.tsx`, рендерится только в браузере). Шаг 1 — ФИО, email, страна (без RU/BY/IR/KP/CU/SY — Paddle их не обслуживает), регион, город, индекс, адрес, компания и ИНН/БИН/VAT. `POST /api/billing {action:"checkout", plan, details}` → Paddle customer + address (+ business) → таблица `BillingProfile` (создаётся сама, raw SQL, `lib/billing/profile.ts`) → transaction с `custom_data {workspaceId, plan}`. Шаг 2 — карта вводится во встроенной форме Paddle (Paddle.js inline, `frameTarget: lemiri-paddle-frame`). Номер карты к Lemeri не попадает; API отвергает похожие на карту данные (`CARD_DATA_NOT_ACCEPTED`).
- **Смена тарифа:** живая подписка Paddle меняется на месте (`PATCH /subscriptions/{id}`, `prorated_immediately`), вторая не создаётся. **Портал:** `POST /api/billing {action:"portal"}` → Paddle customer portal (карта, счета, отмена).
- **Вебхук:** `/api/webhooks/paddle` (и `/api/webhooks/stripe`) — один маршрут `api/webhooks/[type]/route.ts`, обработчики `lib/billing/paddle-webhook.ts` / `stripe-webhook.ts`. Подпись `Paddle-Signature` (HMAC, 5 минут), события по порядку (advisory lock + последний событие), привязка к пространству по `custom_data`. `transaction.completed` связывает customer/subscription, `subscription.*` ставит план, статус (`active/trialing/past_due/paused/canceled`), период и `cancelAtPeriodEnd`.
- В Paddle включить события: `transaction.completed`, `subscription.created`, `subscription.updated`, `subscription.activated`, `subscription.canceled`, `subscription.past_due`, `subscription.paused`, `subscription.resumed`. URL: `https://lemeriai.com/api/webhooks/paddle`. Домен lemeriai.com одобрить в Paddle (Checkout → Website approval), default payment link — `https://lemeriai.com/app/checkout`.
- CSP разрешает `cdn.paddle.com` (скрипт) и `*.paddle.com` (frame, connect).

### Лимиты и экономика
- Лимит считается в **ответах ИИ за период**: событие `AnalyticsEvent` с типом `AI_RESPONSE`. Период — календарный месяц, внутри платного периода — с его начала.
- Значения по умолчанию: Trial — 150, Starter — 2000, Custom — 2000. Меняются через env `LEMIRI_LIMIT_TRIAL_MESSAGES`, `LEMIRI_LIMIT_STARTER_MESSAGES`, `LEMIRI_LIMIT_CUSTOM_MESSAGES`.
- **Расчёт на октябрь 2026.** OpenAI `gpt-4.1-mini` стоит $0.40 за 1M входных и $1.60 за 1M выходных токенов (эмбеддинги `text-embedding-3-small` — $0.02 за 1M, копейки).
  - Один ответ — примерно 5–6 тыс. входных токенов (промпт, знания, история) и 0.3–0.6 тыс. выходных. Это ≈ $0.0025–0.0035, в худшем случае с повтором ≈ $0.007.
  - Starter: 2000 ответов ≈ $5–7 при цене $19. Trial: 150 ответов ≈ $0.5.
  - При смене модели или провайдера пересчитать и обновить env.
- Беседы больше не ограничиваются по количеству: ограничены только ответы ИИ.
- Защита от злоупотреблений: на виджет стоят rate limits — 30 сообщений в минуту на IP+посетителя, 120 опросов в минуту, 5 заявок за 10 минут.

## ИИ-продавец
- **Промпт:** `src/lib/ai/prompt.ts` (`buildSystemPrompt`), используется OpenAI-провайдером. Задаёт правила продаж, правила достоверности (ничего не выдумывать: цены, скидки, наличие, характеристики), сбор заявки и передачу человеку.
- **Профиль продавца:** `src/lib/ai/profile.ts`. Хранится в `AIEmployeeSettings.handoffRules.profile` — JSON, без миграции. Поля: характер, язык, главная цель, доп. цели, ограничения, когда просить контакты, обязательные поля, бюджет, допродажа, ссылка на заказ, политика конфиденциальности, условия передачи.
- **Действия в MVP:**
  - `createLead` — с полями `budget` и `details`, детали пишутся в `Customer.customFields.lead`;
  - `handoffToHuman`;
  - `notifyManager`.

  `createAppointment` модели не передаётся, пока выключен флаг `appointments`.
- **Проверка тарифа** выполняется в `handleIncomingMessage` (оркестратор) **до** вызова модели.
- **Форма заявки в карточке:** `POST /api/widget/[employeeId]/lead`. Требует согласие (`consent: true` и текст согласия). Сохраняет `consentAt` и `consentText` в `customFields.lead`.
- **Сбор заявки — ненавязчиво** (`prompt.ts`, блок COLLECTING A REQUEST): сначала ответ на вопрос; просьба о контактах — максимум одно короткое предложение и только когда разговор к этому подводит (хочет купить/заказать, личная цена, доставка к нему, просит связаться). Не в каждом ответе, не подряд, не на общие вопросы; проигнорировал — не повторяем до нового интереса. Бюджет — только если меняет рекомендацию.
- **ИИ изучает сайт сам** (`src/lib/knowledge/site-*.ts`, `page-read.ts`, `website.ts`):
  - **Кнопка «Изучить сайт»** (`components/sales/site-study.tsx`) — вверху «Карточки и подключения» и «Базы знаний». `POST /api/knowledge/study-site {url?}` (адрес по умолчанию — из разрешённых сайтов карточки или где она замечена; 6 раз в час) → источник WEBSITE + задача `WEBSITE_INGEST`. Её выполняет **отдельный раннер** `site-jobs.ts` (общий `jobs/worker.ts` такие задачи не берёт: иначе краулер копировался в каждый маршрут, +60 KiB) — после ответа `study-site` (GET/POST), после ответа в чате и по cron. Краулер: robots.txt, sitemap.xml, сначала полезные страницы (цены, каталог, контакты, доставка, FAQ), без логина/корзины/кабинета, до 20 страниц, меню/футер вырезаются со 2-й страницы. Страницы сразу в базе знаний (status READY, лексический поиск). `GET` показывает прогресс: STUDYING → SUMMARIZING → READY.
  - **Обзор сайта (ИИ)** (`site-study.ts` → `ensureSiteOverview`) — отдельный документ «Обзор сайта (ИИ)»: компания, товары/тарифы с ценами как на сайте, условия, контакты, FAQ, ссылки только на этот сайт. Пишется не в очереди задач, а после ответа: по опросу `GET study-site` или после ответа в чате (`after()` в `widget/[id]/messages`). Без модели — список страниц.
  - **Во время диалога** (`site-live.ts`, вызывается из оркестратора): в контекст всегда идут обзор сайта и страница, на которой сейчас посетитель (путь приходит из embed: `lemiri:configure {page}` / `lemiri:where`; кеш 10 мин); если сайт ещё не изучен или в знаниях нет ответа — ещё и главная, а пока сайт не изучен — и ссылка с главной, лучше всего подходящая к вопросу (`pickLink`: вопрос о цене → «Тарифы»). Первый диалог на неизученном сайте сам ставит изучение (раз в 6 ч на пространство). Онбординг с адресом сайта тоже запускает изучение.
  - Бюджет Worker: краулер, очередь и чат-часть подключаются через `await import()` — один общий чанк вместо копии в каждом маршруте (иначе +60 KiB gzip).
- **Ответы в карточке** рендерятся безопасно (`RichText` в `website-widget.tsx`): только **жирный**, ссылки `https` и списки. HTML не вставляется.

## Карточка на сайте
- **Встраивание:** `/api/widget/[id]/embed.js`. Скрипт асинхронный, чат-iframe загружается только при первом открытии.
  - Оболочка: `src/lib/floating-card/embed-client.ts` и `runtime.ts`. Это самодостаточный код без импортов: он уходит на сайт клиента как текст.
  - Чат: `/widget/[id]` → `src/components/website-widget.tsx`.
- **Дизайн:** `src/lib/widget/design.ts`. Нормализация и ограничения (цвета только `#rrggbb`, диапазоны размеров, текст без HTML) → `chatVars()` для iframe и `shellConfig()` для оболочки. Хранится в зашифрованном config канала WEBSITE (`widget.*`), поэтому код на сайте клиента не меняется.
- **Премиум-настройки** (поля `Design`: `headingFont`, `accentGradient`, `effects`, `messages`, `composer`, `attention`) добавлены без миграции: `normalizeDesign` дописывает значения по умолчанию в старые сохранённые дизайны.
- **«Подобрать под сайт»:** `POST /api/channels/[id]/match-design {url?, locale}` (Custom, 8 раз за 10 минут). `site-fetch.ts` скачивает страницу и до 4 CSS (только публичные адреса, редиректы проверяются, `LEMIRI_ALLOW_PRIVATE_SITE_FETCH=1` — только для локальных тестов) → `site-style.ts` читает фирменный цвет, фон, шрифты, скругления, тени, тёмную тему → `designFromTokens` (детерминированный дизайн) → ИИ (`jsonCompletion`) правит его патчем, `applyPatch` проверяет значения и контраст. Без модели остаётся детерминированный вариант. Ничего не сохраняется: результат сразу в предпросмотре, «Вернуть как было» или «Сохранить».
- **Разрешённые сайты:** `allowedOrigins`. Токен виджета подписан под origin.
- **CSP:** для `/widget` разрешены Google Fonts и `https:`-картинки (аватар).

## Архитектура и ограничения инфраструктуры
- Next.js 16 (Turbopack) → Cloudflare Workers через OpenNext; Prisma 6 + Neon (HTTP для чтения, WebSocket для записи).
- **Workers Free:**
  - 10 ms CPU;
  - **50 subrequests на запрос** — каждый запрос к БД по HTTP считается;
  - **3 MiB gzip** на бандл, сейчас ≈3051 KiB. Каждый новый маршрут и всё, что импортирует `jobs/worker.ts`, копируется в чанки многих маршрутов — новые страницы лучше делать клиентскими (`dynamic(..., {ssr:false})`) или объединять в один динамический маршрут.

  Рекомендуется Workers Paid.
- Продакшен-кабинет читает данные одним SQL-снимком: `getDirectAppSnapshot` в `src/lib/neon-direct.ts`. Новые поля для кабинета добавлять и туда, и в Prisma-путь `src/app/app/page.tsx`.
- **Автомиграции:**
  - аддитивные, применяются одним запросом (`src/lib/crm/schema.ts`, маркер `_lemiri_schema`);
  - ничего не удалять;
  - новые колонки — только `ADD COLUMN IF NOT EXISTS`.

## Правила работы с отложенным функционалом
1. Не удалять код, таблицы и данные отложенных модулей.
2. Новые функции MVP не должны зависеть от выключенных модулей.
3. Любой новый API отложенного модуля закрывать `featureEnabled(...)` на сервере, а не только в интерфейсе.
4. Не показывать неработающее как доступное: незаконченное — только в блоке «Скоро появится» (`COMING_SOON`).
5. При возврате модуля обновить `docs/FUTURE_FEATURES.md`, `docs/PRODUCT_ROADMAP.md`, тарифы в `offer.ts` и этот файл.

## Проверки
- `npx tsc --noEmit`, `npm test` (node test runner, `tests/*.test.ts`).
- Сборка Worker и размер: `npm run build:cloudflare`, затем `npx wrangler deploy --dry-run --outdir <dir>`.
- Локальный прод-подобный прогон: `wrangler dev` + эмулятор Neon + фиктивная модель. Сценарии лежат вне репозитория.
- Деплой: push в `main` → Cloudflare собирает `npm run build:cloudflare` и деплоит `npm run deploy:cloudflare`.
