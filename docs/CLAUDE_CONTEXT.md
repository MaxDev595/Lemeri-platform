# Lemiri AI — актуальный контекст для Claude

> Читай этот файл перед любой работой с репозиторием. Это источник правды о продукте.
> Если чат-память расходится с этим файлом, верь файлу и обнови его после изменений.

## Концепция
Одна функция → одна проблема → одно решение.

- **Проблема:** бизнес теряет клиентов, потому что посетители сайта не получают своевременную консультацию.
- **Решение:** ИИ-продавец (консультант) в виде карточки чата на сайте. Он круглосуточно консультирует, продаёт, рекомендует товары и собирает заявки.
- Lemiri **не позиционируется** как CRM-платформа, корпоративный инструмент или мультиканальный сервис.
- Не обещаем гарантированного роста продаж или конверсии.
- «ИИ может ошибаться» — пишем на лендинге, в карточке, в кабинете и в документации.

## Разделы кабинета (MVP)
1. **Главная** — диалоги, заявки, ответы ИИ, передачи человеку, состояние подключения, баннер тарифа.
2. **ИИ-сотрудник** (`src/components/sales/employee-studio.tsx`) — профиль продавца и тестовый чат с настоящим ИИ.
3. **База знаний** — `KnowledgeManager` в `platform.tsx`.
4. **Карточка и подключение** (`src/components/sales/widget-studio.tsx`) — дизайн по тарифу, установка с проверкой, ссылка и QR.
5. **Диалоги и заявки** — `InboxView`: диалоги и заявки со статусами Новая / В работе / Успешно / Отказ.
6. **Настройки и подписка** — `SettingsHub`: «Тариф и оплата» (`plan-panel.tsx`) и «Компания и аккаунт».

Всё остальное отложено, см. `docs/FUTURE_FEATURES.md`. Флаги — в `src/lib/features.ts`, env `LEMIRI_FEATURES`.

## Тарифы
| План | Цена | Что даёт | Дизайн-уровень |
|---|---|---|---|
| Trial | $0 / 14 дней | один ИИ-сотрудник, карточка, база знаний, консультации, заявки, ограниченные сообщения | `basic`: цвет, имя, приветствие, сторона, тема, кнопка заявки |
| Starter | $19 / мес | весь ИИ-продавец, история, передача менеджеру, базовая аналитика, повышенные лимиты | `standard`: + аватар, подпись, быстрые вопросы, автооткрытие, 6 готовых стилей |
| Custom | $29 / мес | **всё из Starter** + визуальный редактор карточки | `custom`: палитры для светлой и тёмной темы, 12 шрифтов, размеры, радиусы, тени, рамка, прозрачность, фон-градиент, стиль пузырей, заголовок, иконка/форма/подсказка кнопки, приветственный экран, анимации, мобильные настройки, до 12 своих стилей |

- ИИ в Starter и Custom одинаковый. Custom не получает скрытых функций CRM, каналов и автоматизаций.
- Каталог: `src/lib/billing/plans.ts`. Тексты предложения для лендинга и кабинета: `src/lib/billing/offer.ts`, `COMING_SOON` там же.
- Доступ определяется в одном месте — `resolveAccess()` (`plans.ts`); загрузка из БД — `workspaceAccess()` (`src/lib/billing/access.ts`). Через них работают API, виджет и ИИ.
- **Пробный период:**
  - 14 дней от регистрации владельца — один раз на аккаунт;
  - для аккаунтов, созданных до запуска биллинга, отсчёт идёт от `TRIAL_EPOCH` = 2026-10-10 (env `LEMIRI_TRIAL_EPOCH`).
- **Конец пробного периода или подписки:**
  - ИИ не вызывается — модель не тратит токены;
  - посетитель получает просьбу оставить контакты;
  - форма заявки работает;
  - владелец получает уведомление (не чаще раза в сутки).
- **PAST_DUE:** ИИ работает ещё 7 дней после конца периода, в кабинете предупреждение.
- **Старые планы:** START → STARTER, GROWTH → CUSTOM (`normalizePlan`). Старые price id Stripe распознаются.
- **Даунгрейд:**
  - настройки Custom (`widget.design`, `widget.presets`) остаются в базе;
  - показывается дизайн, доступный тарифу (`resolveLook`);
  - сохранение с меньшего тарифа не удаляет поля старшего (`mergeForTier`);
  - изменить их без Custom нельзя — API отвечает 402 `PLAN_REQUIRED`.
- `LEMIRI_COMP_WORKSPACES` — список id пространств с бесплатным Custom (для своих).

### Биллинг (Stripe, единственный механизм)
- **Цены:** env `STRIPE_STARTER_PRICE_ID` и `STRIPE_CUSTOM_PRICE_ID`. Фолбэк — старые `STRIPE_START_PRICE_ID` и `STRIPE_GROWTH_PRICE_ID`.
- **`POST /api/billing {action:"checkout", plan}`:**
  - если подписки нет — Checkout;
  - если подписка живая — смена цены в существующей подписке с пропорциональным перерасчётом. Второй подписки не создаётся.
- **`POST /api/billing {action:"portal"}`** — Stripe Customer Portal: карта, счета, отмена.
- **Вебхук** `/api/webhooks/stripe` обновляет plan, status и период. Защищён от устаревших событий.

### Лимиты и экономика
- Лимит считается в **ответах ИИ за период**: событие `AnalyticsEvent` с типом `AI_RESPONSE`. Период — календарный месяц, внутри платного периода — с его начала.
- Значения по умолчанию: Trial — 150, Starter — 2000, Custom — 2000. Меняются через env `LEMIRI_LIMIT_TRIAL_MESSAGES`, `LEMIRI_LIMIT_STARTER_MESSAGES`, `LEMIRI_LIMIT_CUSTOM_MESSAGES`.
- **Расчёт на октябрь 2026.** Groq `openai/gpt-oss-120b` стоит $0.15 за 1M входных и $0.60 за 1M выходных токенов.
  - Один ответ — примерно 5–6 тыс. входных токенов (промпт, знания, история) и 0.6–1 тыс. выходных (с reasoning). Это ≈ $0.0015–0.002, в худшем случае с повтором ≈ $0.003.
  - Starter: 2000 ответов ≈ $3–6 при цене $19. Trial: 150 ответов ≈ $0.5.
  - При смене модели или провайдера пересчитать и обновить env.
- Беседы больше не ограничиваются по количеству: ограничены только ответы ИИ.
- Защита от злоупотреблений: на виджет стоят rate limits — 30 сообщений в минуту на IP+посетителя, 120 опросов в минуту, 5 заявок за 10 минут.

## ИИ-продавец
- **Промпт:** `src/lib/ai/prompt.ts` (`buildSystemPrompt`), общий для Groq и OpenAI. Задаёт правила продаж, правила достоверности (ничего не выдумывать: цены, скидки, наличие, характеристики), сбор заявки и передачу человеку.
- **Профиль продавца:** `src/lib/ai/profile.ts`. Хранится в `AIEmployeeSettings.handoffRules.profile` — JSON, без миграции. Поля: характер, язык, главная цель, доп. цели, ограничения, когда просить контакты, обязательные поля, бюджет, допродажа, ссылка на заказ, политика конфиденциальности, условия передачи.
- **Действия в MVP:**
  - `createLead` — с полями `budget` и `details`, детали пишутся в `Customer.customFields.lead`;
  - `handoffToHuman`;
  - `notifyManager`.

  `createAppointment` модели не передаётся, пока выключен флаг `appointments`.
- **Проверка тарифа** выполняется в `handleIncomingMessage` (оркестратор) **до** вызова модели.
- **Форма заявки в карточке:** `POST /api/widget/[employeeId]/lead`. Требует согласие (`consent: true` и текст согласия). Сохраняет `consentAt` и `consentText` в `customFields.lead`.
- **Ответы в карточке** рендерятся безопасно (`RichText` в `website-widget.tsx`): только **жирный**, ссылки `https` и списки. HTML не вставляется.

## Карточка на сайте
- **Встраивание:** `/api/widget/[id]/embed.js`. Скрипт асинхронный, чат-iframe загружается только при первом открытии.
  - Оболочка: `src/lib/floating-card/embed-client.ts` и `runtime.ts`. Это самодостаточный код без импортов: он уходит на сайт клиента как текст.
  - Чат: `/widget/[id]` → `src/components/website-widget.tsx`.
- **Дизайн:** `src/lib/widget/design.ts`. Нормализация и ограничения (цвета только `#rrggbb`, диапазоны размеров, текст без HTML) → `chatVars()` для iframe и `shellConfig()` для оболочки. Хранится в зашифрованном config канала WEBSITE (`widget.*`), поэтому код на сайте клиента не меняется.
- **Разрешённые сайты:** `allowedOrigins`. Токен виджета подписан под origin.
- **CSP:** для `/widget` разрешены Google Fonts и `https:`-картинки (аватар).

## Архитектура и ограничения инфраструктуры
- Next.js 16 (Turbopack) → Cloudflare Workers через OpenNext; Prisma 6 + Neon (HTTP для чтения, WebSocket для записи).
- **Workers Free:**
  - 10 ms CPU;
  - **50 subrequests на запрос** — каждый запрос к БД по HTTP считается;
  - **3 MiB gzip** на бандл, сейчас ≈3047 KiB.

  Рекомендуется Workers Paid.
- Продакшен-кабинет читает данные одним SQL-снимком: `getDirectAppSnapshot` в `src/lib/neon-direct.ts`. Новые поля для кабинета добавлять и туда, и в Prisma-путь `src/app/app/page.tsx`.
- **Автомиграции:**
  - аддитивные, применяются одним запросом (`src/lib/crm/schema.ts`, маркер `_lemiri_schema`);
  - ничего не удалять;
  - новые колонки — только `ADD COLUMN IF NOT EXISTS`.

## Правила работы с отложенным функционалом
1. Не удалять код, таблицы и данные отложенных модулей.
2. Новые функции MVP не должны зависеть от выключенных модулей.
3. Любой новый API отложенного модуля закрывать `featureEnabled(...)` на сервере, а не только в интерфейсе.
4. Не показывать неработающее как доступное: незаконченное — только в блоке «Скоро появится» (`COMING_SOON`).
5. При возврате модуля обновить `docs/FUTURE_FEATURES.md`, `docs/PRODUCT_ROADMAP.md`, тарифы в `offer.ts` и этот файл.
